# 班级访谈关系网络的数据构建与 Gephi 可视化分析

## 摘要

本研究以班级 44 名同学为节点，以同学之间的访谈关系和共同特征关系为边，构建“访谈层”和“实质关联层”两个网络。其中，访谈层包含 44 名同学的全部无向配对，共 946 条边；实质关联层根据同组、同乡、共同爱好、共同特长、共同教师偏好、音乐影视与阅读偏好以及相同课程汇报主题等条件生成，共 307 条边。本文说明了数据字段、变量权重、建边规则、Gephi 导入方法和网络分析思路，并对节点度数、加权度数、网络密度和社群结构等指标进行解释。研究结果表明，访谈层是完整网络，适合分析访谈覆盖情况和互动强度；实质关联层更适合识别同学之间的共同特征、核心节点和潜在社群。

**关键词：** 社会网络分析；访谈网络；Gephi；节点度数；社群发现

## 一、问题背景

班级同学之间的交流不只受到座位或小组划分的影响，也可能与家乡、兴趣爱好、特长、课程经历和媒体偏好等因素有关。仅依靠访谈记录，可以得到“谁访谈了谁”的关系，但难以说明关系形成的原因。因此，本次作业把同学关系拆分为两个层次：

1. **访谈层：** 记录 44 名同学之间是否进行过访谈，以及访谈主题、时长和互动强度。
2. **实质关联层：** 只保留具有明确共同特征的同学配对，分析哪些同学更可能形成实质联系。

通过两层网络的对比，可以观察访谈覆盖是否完整，也可以进一步分析兴趣、经历和背景在班级关系中的作用。

## 二、数据说明

### 2.1 节点数据

节点表共 44 行，每行代表一名同学。为保护隐私，姓名使用“学生01”至“学生44”的匿名标签，节点编号为 `S01` 至 `S44`。

**数据生成说明：** 本次作业中的 44 名同学节点属性及访谈关系数据由 AI 根据分析任务辅助生成，并经过结构化整理后用于 Gephi 网络分析。数据中的姓名、家乡、兴趣、特长、课程经历和媒体偏好均为课堂演示数据，不代表真实同学的个人情况。

44 名同学被分为 11 组，每组 4 人。节点属性包括：

| 属性类别 | 字段 | 说明 |
|---|---|---|
| 基本身份 | `Id`、`Label` | 节点唯一编号和 Gephi 显示名称 |
| 分组信息 | `小组编号`、`小组名称` | 标识同学所在的 4 人小组 |
| 个人特征 | `性别`、`家乡省份`、`家乡城市` | 用于观察班级成员构成 |
| 兴趣特长 | `兴趣爱好`、`特长1`、`特长2` | 用于识别共同爱好和共同能力 |
| 课程经历 | `课程汇报经历`、`汇报次数`、`汇报主题` | 表示是否进行过课程汇报及相关主题 |
| 教师偏好 | `最喜欢的老师` | 用于分析教师偏好是否形成关联 |
| 文化偏好 | `喜欢的音乐类型`、`喜欢的电影类型`、`阅读偏好` | 用于补充共同文化兴趣 |
| 行为特征 | `性格倾向`、`沟通风格` | 用于可视化分组和结果解释 |
| 能力特征 | `编程能力`、`组织能力` | 用于辅助解释节点差异 |
| 综合标签 | `标签` | 汇总小组、家乡、兴趣和音乐等信息 |

### 2.2 访谈层

访谈层采用无向网络。任意两名同学之间只保留一条边，因此可能的配对数量为：

\[
C(44,2)=\frac{44\times43}{2}=946
\]

访谈层共有 946 条边，其中组内访谈边 66 条，跨组访谈边 880 条。边数据包含以下字段：

| 字段 | 含义 |
|---|---|
| `Source`、`Target` | 访谈关系两端对应的节点编号 |
| `Type` | 边类型，统一为 `Undirected` |
| `Weight` | 综合互动强度，范围 1.0 至 5.0 |
| `关系类型` | 组内访谈或跨组访谈 |
| `访谈主题` | 根据共同特征生成的主要谈话方向 |
| `访谈轮次` | 组内访谈为第 1 轮，跨组访谈为第 2 轮 |
| `访谈时长分钟` | 模拟访谈时长 |
| `互动强度` | 高、中、一般三个等级 |
| `访谈状态` | 已完成 |

访谈权重以 1.0 为基础分，各变量采用不同权重：同组 +0.8，同城 +0.8，同省但不同城 +0.4，共同爱好 +1.2，每个共同特长 +0.8，共同教师偏好 +0.5，共同音乐类型 +0.6，共同电影类型 +0.4，共同阅读偏好 +0.3，相同课程汇报主题 +0.3。最终权重上限为 5.0。该权重用于表示互动程度，而不是实际的心理学测量结果。

### 2.3 实质关联层

实质关联层不预先保证 946 条边，而是逐对检查两名同学是否具有共同属性。达到最低关联分数 2.0 的配对才写入边表。各变量权重如下：

| 关联维度 | 分值规则 |
|---|---:|
| 同组 | +1.0 |
| 同城 | +2.5 |
| 同省但不同城 | +1.5 |
| 共同爱好 | +3.0 |
| 每个共同特长 | +2.0 |
| 共同喜欢的老师 | +1.5 |
| 共同音乐类型 | +2.0 |
| 共同电影类型 | +1.5 |
| 共同阅读偏好 | +1.0 |
| 相同课程汇报主题 | +1.0 |

一对同学可能同时满足多个条件。例如，两名同学既喜欢同一种音乐，又具有共同特长，则对应边会同时记录“共同音乐偏好”和“共同特长”。这样既能保留关系形成的原因，也能通过 `Weight` 比较关系强弱。

当前实质关联层共有 307 条边，包含以下字段：

| 字段 | 含义 |
|---|---|
| `Source`、`Target` | 具有实质关联的两名同学 |
| `Weight` | 各项共同特征的加权总分 |
| `关联维度` | 形成关联的属性类别，多类用加号连接 |
| `关联项` | 具体的共同爱好、特长、音乐类型等信息 |
| `共同维度数` | 该边涉及的关联类别数量 |
| `是否同组` | 两名同学是否属于同一个 4 人小组 |

## 三、Gephi 导入步骤

### 3.1 导入节点表

1. 打开 Gephi，选择“文件 -> 导入电子表格”。
2. 选择 `01_节点表_44人_变量加权版.csv`。
3. 将导入类型设置为“节点表”。
4. 字符编码选择 UTF-8，分隔符选择逗号。
5. 确认 `Id` 作为节点唯一标识，`Label` 作为显示名称。
6. 将其他文本字段设置为字符串属性。

### 3.2 导入访谈层

1. 再次选择“文件 -> 导入电子表格”。
2. 选择 `02_访谈层边表_946条_变量加权版.csv`。
3. 将导入类型设置为“边表”。
4. 确认 `Source` 和 `Target` 分别对应边的起点和终点。
5. 确认 `Type` 为 `Undirected`，并将 `Weight` 设置为数值型。

### 3.3 导入实质关联层

1. 如需分层分析，可新建一个 Gephi 工作区。
2. 先导入同一份节点表，再导入 `03_实质关联层边表_变量加权版.csv`。
3. 确认 `Source`、`Target` 与节点表中的 `Id` 完全一致。
4. 将 `Weight` 设置为数值型，其他字段设置为字符串属性。

若在同一工作区中同时导入两张边表，可以为不同图层分别生成子图，或在“数据资料”中先启用、禁用对应边表，避免把两层关系混成一个网络。

## 四、分析设计

### 4.1 网络整体结构

在实质关联层中，当前网络的主要指标如下：

| 指标 | 结果 |
|---|---:|
| 节点数 | 44 |
| 边数 | 307 |
| 网络密度 | 0.3245 |
| 平均度数 | 13.95 |
| 最小度数 | 11 |
| 最大度数 | 17 |
| 平均加权度数 | 47.9 |
| 最小加权度数 | 35.5 |
| 最大加权度数 | 58.5 |
| 连通分支数 | 1 |

实质关联层由 44 个节点组成一个完整连通分支，没有孤立节点。这意味着每名同学至少与一部分同学存在明显的共同特征，班级不存在完全脱离实质关系网络的人。

### 4.2 节点中心性

节点度数表示一名同学直接连接的实质关联边数量，加权度数则同时考虑关联强度。当前度数较高的节点包括：

| 节点 | 标签 | 小组 | 度数 | 加权度数 |
|---|---|---|---:|---:|
| S42 | 学生42 | G11 | 17 | 58.5 |
| S15 | 学生15 | G04 | 17 | 48.5 |
| S07 | 学生07 | G02 | 16 | 55.0 |
| S10 | 学生10 | G03 | 16 | 55.0 |
| S35 | 学生35 | G09 | 16 | 54.0 |
| S43 | 学生43 | G11 | 16 | 54.0 |

这些节点具有较多的共同属性，因此更容易成为网络中的连接点。需要注意，度数高只表示“共同特征对应的边较多”，不能直接解释为现实中人缘最好或沟通能力最强。

### 4.3 关联类型构成

不同关联维度在边表中出现的次数如下。由于一条边可以同时包含多个维度，各项次数之和大于 307。

| 关联维度 | 出现边数 |
|---|---:|
| 共同特长 | 160 |
| 共同教师偏好 | 68 |
| 共同音乐偏好 | 100 |
| 共同影视偏好 | 60 |
| 共同阅读偏好 | 54 |
| 相同汇报主题 | 47 |
| 共同爱好 | 40 |
| 同乡 | 12 |
| 同组 | 7 |
| 同省但不同城 | 2 |

从结果看，共同特长和共同文化偏好构成了实质关联层的重要组成部分。同组关系本身只贡献较小的权重，因此只有 7 条组内配对达到实质关联条件，其余 300 条边均为跨组关联。这说明小组划分与兴趣、特长等实质关系并不完全重合。

### 4.4 不加权重与加入权重的对比

不加权重的分析把所有存在的边视为同等重要，只关注网络中有没有关系、节点连接了多少其他节点；加入权重后，每条边还会根据共同特征的多少和重要性体现强弱。因此，两种方法并不是互相替代，而是分别回答“关系范围有多广”和“关系强度有多高”两个问题。

#### （1）整体指标对比

| 对比项目 | 不加权重 | 加入权重 |
|---|---|---|
| 边的处理方式 | 每条实质关联边都记为 1 | 按 `Weight` 区分强弱 |
| 边数 | 307 | 307 |
| 连通分支数 | 1 | 1 |
| 平均度数 | 13.95 | 不适用 |
| 平均加权度数 | 不适用 | 47.9 |
| 节点度数范围 | 11-17 | 不适用 |
| 节点加权度数范围 | 不适用 | 35.5-58.5 |
| 主要用途 | 判断连接范围和节点数量位置 | 判断关系强度和高强度核心节点 |

加入权重不会自动改变边的数量和图的基本拓扑，因为 307 条边仍然全部保留。权重的作用体现在统计指标、节点排序、布局和筛选结果中。网络中所有节点仍然属于同一个连通分支，说明即使考虑关联强度，44 名同学之间也没有出现结构上的完全断裂。

#### （2）核心节点排序对比

| 节点 | 不加权度数 | 加权度数 | 对比解释 |
|---|---:|---:|---|
| S42 | 17 | 58.5 | 两种指标都最高，连接数量多且关系总体较强 |
| S15 | 17 | 48.5 | 连接数量多，但单条关系的平均强度较低 |
| S02 | 15 | 55.5 | 连接数量不是最多，但高强度关系使其加权排名明显上升 |
| S05 | 14 | 54.5 | 连接范围较小，但关系质量较高 |
| S01 | 14 | 54.0 | 不加权时排名不算靠前，加入权重后进入高加权节点行列 |

从排序变化可以看出，不加权分析更容易发现“连接范围广”的同学，而加权分析能够发现“连接数量不一定最多、但共同特征更丰富”的同学。例如，S15 在不加权分析中与其他高度数节点接近，但加权度数明显低于 S42、S02 和 S05。因此，在解释核心节点时不能只使用一种指标，应当同时报告 `Degree` 和 `Weighted Degree`。

#### （3）强关系子网络对比

为了进一步比较权重的作用，可以按 `Weight` 筛选强关系子网络：

| 条件 | 边数 | 连通分支数 | 最大分支节点数 | 度数范围 | 平均度数 |
|---|---:|---:|---:|---:|---:|
| 不加权，保留全部边 | 307 | 1 | 44 | 11-17 | 13.95 |
| `Weight >= 3` | 93 | 1 | 44 | 3-6 | 4.23 |
| `Weight >= 4` | 72 | 2 | 22 | 2-5 | 3.27 |

当筛选条件为 `Weight >= 3` 时，网络仍保持完整连通，说明高权重关系足以把全部 44 名同学连接起来，但网络由“范围较广的一般关系”收缩为“较少但更强的核心关系”。当阈值提高到 `Weight >= 4` 时，网络分裂为两个连通分支，说明进一步强化关系筛选后，班级中出现了两个相对分离的高强度关系群体。

这部分对比说明：不加权网络适合描述全班关系的整体覆盖，加权网络和强关系子网络适合识别真正紧密的联系。实际分析时应先报告全网络，再报告加权指标和强关系筛选结果，避免只展示一个阈值而遗漏弱关系。

### 4.5 社群发现与分组比较

在 Gephi 中可运行 `Community Detection -> Modularity`，选择默认分辨率并计算模块度。建议重点比较：

1. 算法划分出的社群数量与现有 11 个小组是否一致。
2. 社群内部成员是否具有相同的音乐类型、特长或家乡背景。
3. 跨组边较多的同学是否在可视化中位于不同社群之间。
4. 模块度较高时，说明网络中存在明显的兴趣或经历聚集。

社群结果反映的是当前数据中的共同属性结构，不能直接等同于真实班级中的人际小团体。为了避免过度解释，应结合边的 `关联项` 和节点属性进行人工核对。

## 五、可视化建议

### 5.1 访谈层

访谈层本身是完整图，所有节点度数相同，因此不建议只根据节点大小观察差异。可以重点使用以下编码：

- 节点颜色：按 `小组编号` 或 `性别` 分区。
- 边颜色：区分 `组内访谈` 和 `跨组访谈`。
- 边粗细：映射 `Weight`。
- 标签：只显示部分节点，避免 946 条边和 44 个标签互相遮挡。
- 布局：使用 ForceAtlas2，并开启防止节点重叠。

访谈层的主要结论应是“访谈覆盖完整”，而不是“中心性差异明显”。更有意义的分析是观察哪些访谈边的权重较高，以及组内与跨组访谈的强度差异。

### 5.2 实质关联层

实质关联层更适合用于核心节点和社群分析。建议使用以下视觉编码：

- 节点大小：映射 `度数` 或 `加权度数`。
- 节点颜色：映射 `小组编号`、`性别`、`喜欢的音乐类型` 或 `家乡省份`。
- 边颜色：按 `关联维度` 分区，观察不同关系类型的分布。
- 边粗细：映射 `Weight`。
- 过滤器：筛选 `Weight >= 3`，查看强关联子网络；再与完整网络比较。
- 布局：ForceAtlas2 或 Fruchterman Reingold，关闭高速移动，逐步降低重力。

为了避免图像过于密集，可以在导出前隐藏低权重边，或者把完整图和强关联图分别保存。

## 六、结果解读

根据当前模拟数据，可以形成以下分析思路：

1. **访谈覆盖完整。** 44 名同学之间形成 946 条无向访谈边，说明访谈层是完整图，所有同学都被纳入网络。
2. **实质关系并不只发生在组内。** 实质关联层中同组边只有 7 条，跨组边有 300 条，说明共同兴趣、共同特长和文化偏好可以跨越小组边界。
3. **共同特长是主要连接来源。** 共同特长出现于 160 条边中，是当前数据中最常见的关联维度。
4. **文化偏好形成较多弱到中等强度关联。** 共同音乐、电影和阅读偏好合计涉及较多边，但其单项权重低于共同爱好和共同特长，适合作为辅助解释因素。
5. **核心节点需要结合加权度数理解。** 度数高的同学具有更多直接关联，但中心性结果只说明属性结构位置，不代表现实中的社会地位。

## 七、研究局限

1. 本次数据由 AI 辅助生成，主要用于课堂网络分析演示。姓名、个人属性及访谈关系均不代表真实同学，也不应据此评价任何个人。
2. 访谈权重和实质关联权重是人为设定的计算规则，会直接影响网络密度、中心性和社群结果。
3. 兴趣、音乐和阅读偏好来自单次记录，没有考虑时间变化和多选情况。
4. 访谈关系使用无向边，无法表示“甲主动访谈乙、乙访谈甲较少”的方向差异。
5. 网络分析可以发现关联结构，但不能直接证明某种属性是现实关系形成的原因。

## 八、结论

本文构建了一个包含 44 个节点、946 条访谈边和 307 条实质关联边的班级网络。访谈层和实质关联层均采用分变量权重，其中共同爱好、同城、共同特长和共同音乐的权重较高，同组、同省和阅读偏好的权重较低。访谈层适合展示同学之间的访谈覆盖和互动强度，实质关联层适合观察共同特征、核心节点和社群结构。两层网络结合使用，可以避免把“访谈过”简单等同于“关系更好”，也让家乡、兴趣、特长、教师偏好和文化偏好等因素进入分析过程。

权重对比表明，不加权分析适合观察连接的覆盖范围和一般结构，加权分析适合识别紧密关系和高强度核心节点。后续可使用 Gephi 的度数统计、加权度数、模块度和社团可视化功能，进一步比较不同属性的聚集程度，检验小组划分与真实兴趣结构是否一致。
